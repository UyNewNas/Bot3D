## 2. 各文件的权威边界

- requirements.md：需求文字、AC、需求状态和唯一追踪矩阵。
- backlog.md：开发任务的交付物、依赖与开发状态；迭代文件只选择任务，不复制维护状态。
- test-plan.md：测试定义和环境切片。测试结果只记在实际 AR 记录中，不在计划里预填 PASS。
- acceptance.md：闸门、验收规则、记录索引与模板；实际判定留在对应 AR 中。
- iterations/：该轮目标、范围、出口与排除项；records/：不可抹除的执行、失败、修复和验收证据。
- design/：技术契约的依据。跟踪状态不是机器人命令状态，不能借建台账另造一套执行协议。

同一事实只在权威位置维护；通过稳定 ID 关联。需求、任务、测试不得删除后复用编号；取消范围保留原因和替代项。

## 3. 每轮的需求—开发—测试—验收循环

1. **需求就绪**：写清目标、边界、AC、前置条件、来源和所需证据层级；锁定该轮要验证的子场景。READY 是可开始首次切片，不是用户已签收全部方案。
2. **选择迭代**：从台账选依赖可满足的任务；列本轮必须通过的测试切片、参数和退出条件，不承诺未估算的日历工期。
3. **开发**：开始时记执行角色、环境与任务状态；实现、测试和运行说明一起交付，不铺无用途的空壳模块。每位执行者默认只推进一个 DOING 任务。
4. **测试**：按测试 ID、环境、子场景记录输入、预期、实际结果和复现命令。失败或未运行也按实际状态记录。原始输出和校验清单按 AR 编号在本地留存。
5. **验收**：逐 AC 核对交付物与证据，给出结论、验收角色和未满足项。必测失败 / 阻塞 / 跳过均不能通过；未指定验收者时保持 PENDING，不替用户签收。
6. **返工或变更**：失败登记 DEF；修复后新增 AR 并回归，不覆盖旧失败。范围或契约变化登记 CHG，注明原因、影响、决策者和回归集合，不默默降低 AC。
7. **收尾与下一轮**：同步需求 / 任务状态、记录索引和下一任务。迭代收尾只关闭已验证切片，不把 mock 通过算成 SIM、XR 或 REAL 通过。

这套流程不自动授权安装机器人软件、采购、Git 提交 / 推送、外部发布或硬件操作；需要这些动作时按当轮范围和授权分别处理。

## 4. 状态口径

| 对象 | 状态 | 推进规则 |
| --- | --- | --- |
| 需求 | DRAFT、READY、DEVELOPING、TESTING、ACCEPTANCE、ACCEPTED、BLOCKED、DEFERRED | 通常依次推进；失败退回开发 / 测试并关联记录。ACCEPTED 需该需求列出的全部必验阶段闭合 |
| 开发任务 | DRAFT、TODO、DOING、DONE、BLOCKED、DEFERRED | DONE 需交付物、针对性检查 / 测试和运行说明；不等于需求已验收 |
| 测试运行 | NOT_RUN、PASS、FAIL、BLOCKED、SKIPPED | 结果必须绑定环境和子场景；部分子场景 PASS 不代表整个测试或其他环境通过 |
| 验收 | PENDING、PASS、FAIL、BLOCKED | 技术检查结果与产品验收结论分列；不得代签用户或现场批准 |
| 迭代 | PLANNED、ACTIVE、IN_ACCEPTANCE、CLOSED、BLOCKED | CLOSED 需本轮闸门通过；范围变化记录 CHG |

正常等待前序任务不记作异常 BLOCKED；真正阻塞时写原因、解除条件和所影响任务。没有执行过的产品用例统一为 NOT_RUN，而不是失败或通过。

跨阶段需求可以在 G-M1 通过纯内核切片，但在 G-M3 / G-M4 仍有必验项；整体状态不能提前 ACCEPTED。阶段门按该阶段切片判定，不要求 M1 先完成后续平台，也不允许用早期结果豁免后续复验。

## 5. 编号和证据

| 编号 | 含义 |
| --- | --- |
| REQ-001 / AC-001 | 需求和对应验收标准；一个 AC 可包含多条必须同时满足的断言 |
| DEV-M1-01 | 开发任务；后续阶段保留稳定前缀 |
| T01 | 测试定义；同编号可以有不同环境 / 子场景的独立运行 |
| I01 | 迭代；不与里程碑 M1 混用 |
| G-I01 / G-M1 | 迭代 / 阶段闸门；通过一个不表示通过另一个 |
| AR-0001 | 一次实际验证 / 验收尝试；同轮可有多次 |
| DEF-0001 / CHG-0001 | 缺陷 / 变更，登记在提出它的 AR，后续记录引用原编号 |

优先级：P0 为所在阶段硬门槛，P1 为阶段必要质量项，P2 为明确暂缓项。P0 不允许越过环境或授权门槛。

证据层级分开：DOC、UNIT / MOCK、SIM、GATEWAY / XR、REAL、PORTABILITY。迁移证据还必须写清两个目标及共同成功任务；不能只写“接口连通”。

- mock 停车不证明设备停车；数学坐标测试不证明头显跟踪 / 重定位行为。
- 进程崩溃恢复不证明断电持久性；SQLite 配置和存储假设另行记录。
- 当前停车不证明历史命令成功，也不证明旧执行者不会再次生效；UNKNOWN 处置不能改写历史。
- 保存源代码版本；当前仓库无提交时写“未提交工作树”，可记录相关文件哈希，不编造 HEAD。
- 不在证据里保存凭据或默认上传现实影像；本地数据也要有访问、脱敏和保留范围。
