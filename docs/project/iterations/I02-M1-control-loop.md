## 2. 已锁定数据与实现切片

### DEV-M1-05：控制权

人工保护钟为 control-clock、从 0 ns 起；max_lease_ns=100、首次租期 10 ns，测试 9 / 10 / 11 ns；证据窗口 0..1000 ns。绑定 arm-fixture / mock-device-a，镜像只读，另设独立设备。operator-a / operator-b 显式获权，viewer 无控制范围。字段与全部前提见专题设计；这些不是设备安全阈值。

| 当前切片 | 必须证据 |
| --- | --- |
| T01/leases | 配置时设备可写唯一、真实线程竞争单持有者、scope / session / lease 一致、只读镜像拒绝 |
| T07/authority-loss | 释放 / 到期 / 失联 / 撤权事件、拒绝不丢效果、旧身份不能复活、原绑定与聚合未结执行原子撤权，处置后重新申请 |
| T30/activation | READY / lease / ARMED / motion 分离，明确确认与全部前提，健康自身运动可续租；能力上下文变化退役旧绑定，旧证据不能复活 |
| T42/lease-clock | 半开到期、范围校验、独立源钟、时钟失效保守撤权与保护入口仍可调用 |

该工作包只验证控制权部分；T07 的实际 STOP、T30 的完整命令超时联动、T42 的命令期限 / 执行预算未由该工作包完成。未知反馈继续明确未知，后续完整 StateProjection 单独验证。

### DEV-M1-06：命令摘要与内存 Journal

继续使用人工 control-clock；命令 fixture 的接受期限为 100 ns、下发期限 200 ns、执行预算 300 ns，均为结构验证输入，不是实际设备阈值。同键插入用 8 个线程和屏障验证，追加版本竞争用 2 个线程验证；不用随机 sleep 构造顺序。写入故障在真实内存适配器的底层 mapping 注入，区分写前失败、写后确认丢失和读失败。

| 当前切片 | 必须证据 |
| --- | --- |
| T02/digest-retry | 固定规范编码，request_id、q 符号与负零等价；同键并发只创建一份记录，原绑定 / 会话 / 检查引用不被重试覆盖 |
| T03/digest-conflict | 逐项变更执行字段、相邻有限浮点值、UUID / robot 作用域；非法输入拒绝，冲突不覆盖原记录 |
| T02/journal-order | 候选与公开 ACCEPTED 分开，PLANNING 先于唯一意图，原句柄和状态顺序可核对；追加版本 / entry 去重有效，终态不改写，迟到事实可追加 |
| T18/journal-fault | 候选 / 意图 / 终态写前失败和写后确认丢失，读失败不报缺失；未知键明确异常，新写入锁定，旧快照不变 |

当前切片不连接控制权管理器或外部执行者。日志内部顺序不替代协调器的实际接受 / 最后下发裁决；T18 的拒新运动与 STOP 独立通路仍由 08 / 09 / 16 联调，SQLite 与跨进程恢复留 I03。
