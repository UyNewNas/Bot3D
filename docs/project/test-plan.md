## 1. 运行单位与前置条件

一次结果必须定位到“测试 ID＋环境＋子场景＋代码 / 配置版本”；不能只写“T15 通过”。开始迭代时锁定所选子场景、输入、时钟、阈值、预期调用顺序和证据位置。新增子场景沿用测试 ID，不删除或复用原编号。契约变化走 CHG，失败走 DEF，实际结果只追加到 AR。

每次运行至少保存：开始条件与执行角色、输入 / 故障位置、预期、实际、运行命令及退出码、原始输出、后端调用 / 事件顺序、恢复步骤和限制。正常路径不能只检查拒绝逻辑；故障路径不能只检查返回码而不检查是否误下发和是否解锁。

测试前核对环境与权限。UNIT / MOCK 不建立设备连接；SIM 固定模型和控制器；REAL 必须另有设备授权、保护证据和具体试验批准。未经授权不运行真实运动或真机故障注入，保持 NOT_RUN / BLOCKED，不用 SKIPPED 放行必验项。

## 2. 证据层级

| 环境 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| DOC | 定义、来源、追踪、设计评审和本地静态检查 | 产品实现、运行正确性和用户签收 |
| UNIT / MOCK | 纯数学、内核规则、虚拟时钟、可控外部响应及调用顺序 | ROS 联调、真实停车、XR 跟踪或断电持久性 |
| SIM | 锁定 ROS / 仿真组合中的实际反馈、执行与停止 | REAL 物理保护、真实模型误差和现场批准 |
| GATEWAY / XR | 真实 HTTP / WS、前端 / 头显输入、坐标和跟踪失效 | 仅由数学测试或前端动画推断的机器人完成 |
| REAL | 指定设备、版本、标定及批准工况中的观测 | 其他设备、负载、版本或未批准故障条件 |
| PORTABILITY | 两个明确目标使用相同任务代码完成共同任务 | 仅接口连通、缺能力拒绝或模型成功导入 |

MOCK 中用 SIM / REAL 标签验证绑定隔离，证据仍是 MOCK。异常抛出、进程被终止、存储掉电是不同故障模型，必须分开记录。

## 4. 必须细化的关键脚本

### T31：最终下发与停止排序

DEV-M1-01 交付可执行测试设计，DEV-M1-09 实现脚本。 设计基线与 DOC 模型运行说明见[运行时详细设计](../design/05-runtime-coordination.md)；模型输出不计作产品测试结果。用屏障 / 事件和可统计后端控制交错，不依靠随机 sleep 碰竞态。至少覆盖：

1. 规划未返回时 STOP，随后旧规划才返回。
2. 下发意图提交前 STOP；提交已在途时也要控制返回顺序。
3. 意图已提交、任务已排入工作线程，但尚未越过最后下发边界时 STOP。
4. 最后下发边界先于 STOP，外部调用尚未受理 / 已受理 / 受理响应丢失三种情况。
5. STOP 回执先到，但旧外部结果 / 反馈后到；以及停止路径遇普通日志阻塞。

每种顺序记录协调序号、边界裁决、任务撤销标记、execute / query / stop 的次数和顺序、业务槽、物理锁与 arming。边界前撤销的任务不得后来调用外部执行；边界后不能证明未受理时按可能执行处理，停止并对账。不能只在“放进线程池前”检查一次租约，就宣称解决“线程稍后才调用 SDK”的窗口。SIM / REAL 适配器还须证明本地执行者与该边界的实际关系，epoch 字段本身不是设备 fencing。

### T09 / T34：崩溃与三类未知

在接受持久化之前、之后，意图之前、之后，最终下发之前、之后，外部受理和句柄 / 终态记录前后分别建立可定位故障点。存储异常与实际子进程终止分别运行；重启使用独立检查进程和同一持久化数据，不以清空数据库制造恢复成功。

每个故障点分别列出：历史命令能否确定、现在能否证明停车、旧执行者能否再生效、允许哪些只读查询 / 停止、解锁所需证据与权限。UNKNOWN 的历史事实保留，后续对账追加新事实。没有停车证据，或旧执行者仍可能生效，均不能仅靠换 epoch 或人工点选解锁。不宣称 SQLite 本地事务与设备动作原子提交或物理 exactly-once。

### T27 / T37—T40：正常完成与迁移

先固定共同任务、输入目标、成功误差和停车窗口，再运行。记录任务级代码版本 / 哈希、两个目标身份、各自能力和环境版本、允许变化与实际差异、实际反馈、误差及限制。必须两端成功；只连通、只动画、只导入模型、只返回“缺能力”不能关迁移 AC。新硬件的 REAL 权限单独审查。

## 5. 参数锁定与执行记录

- UNIT / MOCK 的参数是显式人工测试数据，不冒充真实机器人安全阈值；首轮基准见 [I01](iterations/I01-M1-foundation.md)。
- 时钟比较、四元数容差、状态新鲜度、静止窗口、目标误差、队列容量、负载和停止预算在各轮 AR 开始前锁定；未锁定时不能判相关用例 PASS。
- 时延分接受 / 规划 / 下发 / 反馈 / 停车测量，记录样本数、负载、最大值和异常；有足够样本再报告百分位，不用均值掩盖超限。
- 每阶段必验集合见[闸门定义](acceptance.md)，每条 AC 的开发 / 测试映射只查 requirements.md，不另维护第二张矩阵。
- 失败先保存实际输出与 DEF；修复后新增 AR 并回归同子场景。NOT_RUN、BLOCKED、SKIPPED 与 FAIL 不互相冒充，必测未通过不得收尾。
