## 1. 验证策略

先证明控制与失效语义，再接入仿真，然后接入 XR，最后在另行授权和满足条件后验证真机。每个阶段需要独立证据；不能用 mock 通过代替仿真通过，也不能用仿真通过代替真机验证。

最小垂直切片为：发现机器人 → 获取有效能力 → 申请控制权 → 预览目标 → 确认目标 → 规划 → 单一路径执行 → 实际状态反馈 → 完成 / 停止确认。

## 2. 分阶段交付

| 阶段 | 工作 | 出口条件 | 当前状态 |
| --- | --- | --- | --- |
| M0：设计基线 | 调研、边界、领域与适配契约、风险清单 | 文档一致、相对链接与示例可检查；实现前评审关键状态和时序 | 本轮形成草案，未完成运行验证或用户定版 |
| M1：纯内核 + mock | 最小 Python 工程、领域类型、租约、串行协调器、幂等与日志；不依赖 ROS / Unity | 用确定性虚拟时钟和 mock 后端通过核心 / 故障测试；同 ID 最多一次应用下发 | 工程与基础类型已交付，下一项为只读发现 |
| M2：单 ROS / 仿真链 | 固定 ROS + Gazebo + 模型 + MoveIt + 控制器组合 | 单一轨迹执行链跑通；实际仿真反馈与目标分离；停止、时钟和失联测试通过 | 未开始 |
| M3：XR + 仿真 | Unity / OpenXR、网关接入、坐标、预览、SIM 标识 | 桌面输入与头显输入共享目标语义；跟踪丢失、重定位、重连不触发旧运动 | 未开始 |
| M4：条件性真机 | 确定设备和权限，先只读，再按批准工况逐步启用运动 | 完整设备卡、标定和风险评估；本地保护及停止证据；同任务代码在真机经验证 | 未授权、未开始 |
| M5：迁移证明 | 加入第二后端 / 第二机器人，重复同一任务级用例 | 主要变更新增适配器、模型与配置；不支持能力明确拒绝；迁移边界有记录 | 未开始 |

M1 不必先铺满所有目录或实现通用插件框架。M2 可以使用测试客户端，M3 可以先使用普通屏幕；不让头显采购或媒体流选型阻塞控制语义验证。

### M4 的额外前置门槛

- 有明确的设备所有者 / 操作者授权和现场操作规程，本轮文档请求不构成真机运动授权。
- 固定设备、控制器、固件、SDK、许可证、驱动与控制模式，确认接口实际有权使用。
- 核验原生控制权和独占条件，排除示教器、其他进程或主机的非预期写入。
- 按厂商规程检查实体急停、隔离区域、本地限位、设备侧看门狗、失联与停车反馈。特别验证网关失活但驱动仍在线的情况，不能假定 ROS Action 客户端退出就会取消轨迹。
- 先只读核对设备身份、关节 / 工具 / 坐标和状态质量；再由现场负责人员批准低风险、低速、有限范围的离散动作。
- 真机断线、进程崩溃等故障试验必须有独立批准的工况和恢复办法；不能照搬仿真故障脚本到正在运动的设备。
- 停止时延、状态陈旧、时钟不确定度等门槛未确定或未验证时，REAL 保持禁用。

## 3. 核心测试与故障注入清单

以下是最初 T01—T25 的设计摘要，不是已有测试结果。完整测试定义与环境切片以[测试计划](../project/test-plan.md)为准；需求映射只在[唯一追踪矩阵](../project/requirements.md)维护。

| 编号 | 输入 / 故障 | 期望行为 |
| --- | --- | --- |
| T01 | 两个会话同时申请同一机器人 | 只有一个运动租约，另一个得到 BUSY；不同逻辑 ID 不能绕过同一 device_id 的独占 |
| T02 | 同一 command_id、同一请求并发重复发送 | 只接受一次应用执行，重复请求返回原记录；核对后端调用次数，不只看 UI |
| T03 | 同一 command_id 改目标、期限或后端代次 | IDEMPOTENCY_CONFLICT，没有第二次下发 |
| T04 | 请求在网络中延迟至 admit_before_ms 之后 | ADMISSION_EXPIRED，而不是从接收时重新开始 TTL |
| T05 | 规划耗时超过 start_before_ms，或规划完成前撤租 / STOP | 不下发旧计划；释放槽位前证明从未下发或已停车 |
| T06 | 源状态延迟、乱序、重复，接收端却仍不断收到包 | 按源序号、源年龄和时钟质量识别，不把“仍有包”当作实时 |
| T07 | 租约到期、客户端断开、权限被撤销 | 进入 DISARMED，请求停止；确认前保持锁定，不自动授予新操作者 |
| T08 | 后端已受理但响应丢失 | 查询原句柄，不再次 submit；不能对账则 EXECUTION_UNKNOWN |
| T09 | 下发意图写入前 / 后、外部受理前 / 后进程崩溃 | 重启为 DISARMED，新代次，不重放运动；未结记录进入对账 |
| T10 | 停止请求已发出，但反馈缺失或仍在运动 | 不报告 CANCELLED / STOPPED；STOP_UNCONFIRMED，继续阻止新运动 |
| T11 | 命令超时或后端报错，但机器人未确认停车 | 业务可 TIMED_OUT / FAILED，物理状态仍未知或运动；不清空运动锁 |
| T12 | SIM → REAL 切换期间收到旧运动包和旧状态 | 旧代次不得改变新绑定；目标后端先只读，要求新确认与租约 |
| T13 | 旧后端无法确认停止 | 切换保持冻结，不连接为新的可写目标来掩盖旧运动 |
| T14 | 改工具 / 标定 / 模型 / 障碍，或实际关节偏离计划起点 | 旧计划失效；执行前重规划 / 拒绝，执行中按策略停止 |
| T15 | XR 左右手系、四元数符号、不同单位、跟踪原点重置 | 已知基准点 / 姿态转换正确；无效跟踪不产生目标；重定位要求重新确认 |
| T16 | 仿真暂停、加速、重置和时间回退 | 应用超时 / 租约不被暂停；重置使旧上下文失效；REAL 不消费仿真时钟 |
| T17 | 状态 / 图像洪泛、慢订阅者、普通队列满 | 状态合并 / 拒绝 / 重同步；停止与控制权路径不被大数据队列阻塞 |
| T18 | 日志磁盘满、关键记录失败 | 拒绝新运动；授权停止仍可到达可用本地控制链，记录审计缺口 |
| T19 | 错命名空间、joint 顺序、ROS 类型、QoS 或驱动版本 | 启动检查或就绪检查失败；无反馈不得填零伪造成功 |
| T20 | MoveIt 与另一个节点同时尝试执行 | 配置与控制权验收发现冲突；首版仅保留一条实际下发链 |
| T21 | WS 增量中断、游标过期、前端重启 | 读快照和未结命令；不自动重放按钮 / 动作缓存 |
| T22 | 非法用户、越权机器人、任意 topic / SDK / 文件输入 | 拒绝并脱敏审计；普通 viewer 不能通过调试接口下发 |
| T23 | 不可达目标、缺失能力、超范围参数、无效四元数 | 可解释拒绝，不自动改成其他控制模式或放大容差 |
| T24 | 网关 / 驱动失联，包含网关消失但驱动仍在线 | 在经批准的条件下验证设备侧看门狗 / 本地守护；不把软件 STOP 测试冒充该证据 |
| T25 | 示教器改变模式、外部程序运动或保护状态改变 | 更新真实状态、取消激活并锁住新运动；不把应用租约当作物理独占证明 |

M1 使用可控时钟、可注入的存储 / 后端和可统计的执行调用。M2 / M3 重复适用用例；M4 只在获准条件下执行适合该硬件的测试，并保存不同层级的证据。

## 4. 预算与测量

不预先承诺通用于所有设备的“1 kHz 控制”或“零延迟”。实现时逐配置制定并锁定以下预算；未设置的关键门槛不能作为 REAL 激活默认值。

| 指标 | 测量方式 | 决策依据 |
| --- | --- | --- |
| 接受 / 规划 / 下发时延 | 同一网关单调时钟的分段记录 | 交互体验、目标有效期和计算负载 |
| 状态年龄与时钟误差 | 源时间映射、接收时间、偏移不确定度 | 能力所需反馈质量；映射不可信就不使用该年龄作保证 |
| 停止确认时延 | 停止入口、后端请求、可信静止反馈分别打点 | 厂商机制、现场风险评估与批准工况 |
| 失联停车时延 | 经批准测试本地控制链，不依赖已断开的网关 | 设备看门狗与控制器配置 |
| 目标误差 | 区分编码器 / 正运动学误差与外部测量误差 | 工具、负载、标定和任务要求 |
| 资源 / 背压 | CPU、内存、队列、丢弃、图像带宽与长时间运行 | 先保持控制 / 反馈路径可用，再优化媒体 |

记录样本数、负载、P50 / P95 / P99、最大值与异常。涉及物理限制时不能只用平均值或百分位掩盖极端事件。测试报告标明硬件 / 仿真、测量来源和不确定度。

## 5. 怎样证明“可迁移”

| 层次 | 保持不变 | 允许变化 | 所需证据 |
| --- | --- | --- | --- |
| 同机器人 SIM → REAL | 应用任务流程、能力语义、公共消息结构 | 绑定、代次、租约、标定、限制、资产和驱动配置 | 同任务级用例分别通过仿真与真机验收 |
| 同机器人换仿真器 | 领域目标和前端行为 | 模型转换、后端参数、仿真适配 | 差异清单、相同断言和误差范围；不声称数值轨迹一致 |
| 第二机器人 | 能力相同的任务代码 | 适配器、模型、工具、可达空间、规划配置 | 有共同可完成任务；不可达 / 缺能力有明确原因 |
| 第二 XR 前端 / 设备 | 机器人契约与任务用例 | 输入映射、坐标边界、显示 | 相同目标语义与跟踪失效行为 |

判断标准不是“两个机器人能连上”，也不是“把所有差异隐藏在一个 move”。不支持能力时正确拒绝是契约健壮性证据，但不算成功完成任务的迁移证据。若每加一种设备都要在内核写品牌条件分支，应复查抽象；不同能力族有新设计则是正常扩展。

## 6. 每次验收保留的证据

- 测试编号、日期、执行人角色、批准条件和结论；失败 / 未执行也要记录。
- OS、ROS、SDK、固件、引擎 / XR 插件、依赖锁定和源代码版本。
- 设备 / 仿真实例身份、后端配置、模型、场景、工具与标定版本。
- 脱敏命令日志、后端句柄、状态质量、关键事件和必要的 rosbag2 数据。
- 预期与实测差异、已知缺陷、复现步骤与退出 / 恢复方案。

现实环境记录按最小必要原则收集，标明访问与保留策略。回放数据默认只进入隔离的 SIM / 回放会话，不能生成 REAL 写权限。
